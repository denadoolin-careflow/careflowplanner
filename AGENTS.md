# Project architecture decisions

- Planner density is local; habit/routine done-state syncs.
- Past-day routine step completions read/write routine_completions; today's live done flags stay on routines.items. Habit weeklyTarget and skip dates live in habits.meta; routine skips in routines.meta — no schema change.
- Daily rituals reuse daily_checkins for Morning Reset and dated journal entries tagged with the evening-reflection template for Evening Reflection completion, avoiding a duplicate ritual store.
- Ritual step lists (Morning Reset / Evening Reflection) and their per-date check-offs are device-local (localStorage) presentation data; ritual completion itself stays in daily_checkins / journal.
- Ritual steps reuse shared completion visuals/chimes; stable default step IDs keep checks.
- Completed-task strikethrough is a device-local pref shared by all task surfaces.
- Event types (appointment/family/reminder) reuse appointments.type; their colors are device-local (localStorage) like calendar kind colors.
- Today and Planner use page-scoped Soft Botanical mobile presentation tokens and Outfit/Figtree typography, preserving the app-wide theme.
- Today/Planner share ViewPills. Goal pickers/labels share LifeAreaGoalPicker; links use tasks.goal_id, projects.linked_goal_ids, habits.meta.linkedGoalIds, and device-local ritual goal ids in ritual-steps. Explicit task goal clears persist null.
- Day rhythm combines moon, season, cycle and capacity.
- Note properties use notes.properties (jsonb); supertag fields use item_field_values, entity_type 'note'.
- Note block IDs persist as trailing ` ^b-xxxxxx` markers in the markdown body (added only when first linked); block embeds/ref chips persist as data-* HTML so no schema change is needed.
- Notes uses a page-scoped presentation layer derived from the active atmosphere; capture review, pinned density, and per-month notebook appearance are device-local while note/task content preserves existing synced models.
- External note link cards persist as data-web-link-card HTML inside the existing markdown body so rich links round-trip without a schema change.
- Inbox split writing reuses the daily note and rich editor; timestamp sections stay plain markdown with local drafts and serialized autosaves.
- Note table summary rows are recognised by a last row labelled Total/Average/Count and recalculated into plain cell text, so they round-trip in the markdown body without a schema change.
- A note's Project property mirrors notes.project_id (the property value is the project id), so project boards/backlinks keep using the existing column.
- Custom note Spaces sync via the note_spaces table (tags + explicit linked note/task/project ids + hidden ids for unlinks); legacy device-local spaces migrate on first load.
- Main and Notes sidebars share the notebook date tree, driving the gallery month via the Notes URL; expansion is device-local and tree IDs are instance-unique.
- Sidebar Space children use the same explicit links, tag matches, project links, and hidden-item exclusions as the Space hub, so linked navigation stays consistent.
- Tag appearance editing reuses the shared tag store; unused filtering counts existing sources without deleting content.
- NAV_SUBPAGES (nav.ts) drives sidebar branches and page tabs.
- Sidebar hover trees reuse NAV_GROUPS/NAV_SUBPAGES in a portal to escape sidebar clipping.
- Project Linked notes merge note_links and notes.project_id matches, labelling each source.
- Laundry loads sync per account via one laundry_state row (jsonb loads, realtime), cached in localStorage; dryer stage creates a planner task that auto-completes when the load moves on.
- Inbox and Planner share a selected-note schedule pane; the chosen ordinary note is device-local while daily-note following uses the active schedule date.
- My Focus pinboard columns and pins are device-local (localStorage) references to existing task ids, so tasks stay in their original project/area without a schema change.
- Bedside med reminders use the shared medication scheduler and dose logs (not duplicate tasks), so stopping a med cancels reminders but keeps history.
- Bedside recurring meals reuse meal recurrence definitions; dated meal check-offs sync through meal_completion_logs across Bedside, Planner, and Today so recurring days do not share completion state.
- Cosmic visuals reuse skyStatus, monthRhythmMoments and NatalWheel; HousesWheel selects existing details without recalculating.
- Tarot pulls and moon checklists sync via one astro_suite_state row, merged with the local cache on load so no device loses entries.
- Astro math is local; chapters cache by birth/date/version. Rhythm uses exact quarters and dated rituals, preserving duplicate lunations. Phase intentions sync in monthly-note properties, reused by reminders.
- Natal PNGs pre-render for iOS; react-zoom-pan-pinch zoom is separate. Device-local appearance tokens color Natal, Houses and PNGs.
- Wealth net worth compares against monthly net_worth_snapshots (unique user+month); Overview keeps the current month's row live.
- Moon aspect guide is computed locally; placement prefs and check-offs are device-local.
- New-moon goal suggestions derive from monthRhythmMoments plus natal houses (sign fallback); swap/dismiss/added state is device-local per new moon, and Add reuses addGoal/addTask.
- New notes are stamped with rhythm properties (stable rhythm-* ids in notes.properties) at creation; AI summary saves to the ai-summary property via the existing ai-notes summary action.
- Note property/choice icons and colors sync per account in note_property_styles keyed by normalized property name; per-note prop.colors remains a fallback.
- Property-style sync uses an account-scoped pending cache, atomic field-patch RPC and realtime plus foreground refresh, preventing stale devices from replacing unrelated picks.
- Note property display marks and choice chips share PropertyStyleDisplay across editors, gallery cards and rhythm controls so saved styling stays consistent.
- Property colors preserve synced saved values and use shared theme-aware CSS roles; property/selection pickers share one searchable registry and palette, and text properties auto-size while saving on blur to keep summaries readable without changing note content.
- Period note templates (day/week/month prompts, properties, connections) sync in note_period_templates; applying adds only missing headings/properties, and connections read live from existing sources.
- Voice memos store audio in the private note-audio bucket under the user's folder and persist in note bodies as data-voice-memo HTML; transcription runs server-side.
- Append-only dictation consumers use final-result deltas, tracked by recognition-session result index, while live previews replace cumulative text; this prevents replay without removing intentional repeated speech.
- Dictation sessions stay active through graceful stop's final event, and are invalidated before failure/unmount abort; stale recognizers cannot insert into another session or note.
- Voice memos sync via the voice_memos table keyed by storage path; note bodies keep only data-voice-memo markers, and transcript/summary live on the row so the library and note cards stay in sync.
- Moonscape layout (Arc/Tide/Wheel/Journey) is a device-local pref read by the shared Moonscape switcher, so Planner, Moon & Rituals and Settings stay in step.
- Library: books/films/articles in library_items; recipes reuse meals_library so Meals and Library share one recipe store, and 'Add to meal plan' inserts meals rows.
- Cyclical goal extras live in goals.details; an owner-scoped atomic patch RPC and realtime prevent unrelated field overwrites, while missing-only legacy imports preserve synced picks. Compost is a reversible details flag, never deletion, so task/project links and history remain intact.
- Daily focus goal syncs per account per date in daily_focus_goals; Today, Today header chip and Planner day read the same hook.
- Generic cross-item links live in entity_links; Connections merges them with existing built-in link columns (tasks.goal_id/project_id, projects.linked_goal_ids, habits meta, notes.project_id) read-only, and suggestions never auto-link.
- Projects hub views (incl. Journal) are device-local prefs over existing project data; the Journal view's active project is device-local.
- Workspace quiz answers/recommendations sync in workspace_profiles; applying reuses existing goals, Today prefs and profile default_route rather than new visibility settings.
- Project detail page is the Plan/Grow/Care/Let go garden: task phase and Let go disposition live in tasks.garden (separate from done; section-name/Plan fallback is display-only), project intention/energy/next step in projects.details; Add to Today sets is_top_three so no duplicate task or deadline change.
